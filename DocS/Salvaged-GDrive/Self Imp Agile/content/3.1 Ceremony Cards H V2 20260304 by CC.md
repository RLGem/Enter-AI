### כרטיס 1: Daily Standup

```
+========================================+
|         DAILY STANDUP                  |
+========================================+
| TIMEBOX: 15 דקות מקסימום              |
| מתי: כל יום, אותה שעה, אותו מקום      |
| מי חייב: צוות פיתוח + SM              |
| רצוי: PO (שומע/ת, לא מנהל/ת)         |
| לא מוזמן: מנהל/ת                      |
+----------------------------------------+
| כל אחד עונה:                          |
|  1. מה עשיתי מאז ה-Daily האחרון?      |
|  2. מה אעשה היום?                      |
|  3. מה חוסם אותי?                      |
+----------------------------------------+
| כן:                                    |
|  ✅ דבר/י עם חברי הצוות, לא עם ה-SM   |
|  ✅ העלה/י חסימות מיד                  |
|  ✅ עד 2 דקות לאדם                     |
|  ✅ התמקד/י בהתקדמות ל-Sprint Goal     |
+----------------------------------------+
| לא:                                    |
|  ❌ דיונים טכניים (→ חניון)            |
|  ❌ פתרון בעיות (→ אחרי ה-Daily)      |
|  ❌ לחרוג מ-15 דקות                    |
|  ❌ לתת אחד לשלוט בדיון               |
+----------------------------------------+
| SM — בסוף:                             |
|  [ ] הסתיים בזמן                       |
|  [ ] חסימות תועדו עם אחראי            |
|  [ ] פריטי חניון תוזמנו               |
+========================================+
```

### כרטיס 2: Sprint Planning

```
+========================================+
|         SPRINT PLANNING                |
+========================================+
| TIMEBOX: 3-4 שעות (ספרינט 3 שבועות)  |
| מי: PO + SM + צוות פיתוח              |
| לא מוזמנים: מנהלים, לקוחות            |
+----------------------------------------+
| הכנה — לפני הישיבה:                   |
| PO: Backlog מסודר, פריטים עליונים עם  |
|     AC, הצעת Sprint Goal              |
| SM: קיבולת מחושבת, לוח מוכן,         |
|     Velocity מ-3 ספרינטים אחרונים     |
| מפתחים: עברו על Stories מועמדים       |
+----------------------------------------+
| חלק 1 — מה (60 דקות):                |
|  1. PO מציג Sprint Goal מוצע          |
|  2. PO מציג Stories מובילים           |
|  3. הצוות שואל שאלות                  |
|  4. הצוות בוחר לפי קיבולת/Velocity   |
|  5. Sprint Goal סופי — ביחד           |
+----------------------------------------+
| חלק 2 — איך (90-120 דקות):           |
|  1. פירוק Stories ל-Tasks             |
|  2. הערכת Tasks בשעות                  |
|  3. זיהוי תלויות                      |
|  4. אימות: סה"כ ≤ קיבולת             |
+----------------------------------------+
| תבנית Sprint Goal:                    |
| "בספרינט הזה נתמקד ב-[מה]            |
|  כדי לאפשר ל-[מי] ל-[לעשות מה]."     |
+----------------------------------------+
| נוסחת קיבולת:                         |
| (ימי עבודה) × (שעות/יום) × (מפתחים)  |
|  − חופשות − רזרבות − 20% תקורה       |
+========================================+
```

### כרטיס 3: Backlog Refinement

```
+========================================+
|       BACKLOG REFINEMENT               |
+========================================+
| TIMEBOX: שעה אחת לסשן                 |
| תדירות: 1-2 פעמים בשבוע              |
| מי: PO + SM + צוות פיתוח              |
| מטרה: Stories מוכנים ל-2 ספרינטים הבאים|
+----------------------------------------+
| Definition of Ready — 6 תנאים:        |
|  [ ] פורמט User Story (בתור/רוצה/כדי) |
|  [ ] Acceptance Criteria (2-3 לפחות)  |
|  [ ] Story Points מוערכים             |
|  [ ] קטן מספיק (≤8 נק'; 13+ = פרק!) |
|  [ ] אין תלויות פתוחות               |
|  [ ] הצוות מבין את ה-Story            |
+----------------------------------------+
| Planning Poker — הזרימה:              |
|  1. PO מציג Story + עונה לשאלות       |
|  2. כל מפתח בוחר קלף בסתר            |
|     (1, 2, 3, 5, 8, 13, 20)           |
|  3. חושפים בו-זמנית                   |
|  4. גבוה ונמוך מסבירים               |
|  5. הצבעה חוזרת → הסכמה              |
+----------------------------------------+
| כלל הזהב:                             |
| Story ≥ 13 נקודות = גדול מדי.        |
| פרקו אותו לפני שנכנס לספרינט.        |
+========================================+
```

### כרטיס 4: Sprint Review

```
+========================================+
|         SPRINT REVIEW                  |
+========================================+
| TIMEBOX: עד שעתיים                    |
| מי חייב: PO + SM + צוות + לקוח       |
| רצוי מאוד: בעלי עניין                 |
+----------------------------------------+
| סדר יום:                              |
|  פתיחה (10 דק'): PO מציג Sprint Goal, |
|    סיכום ביצוע, מדדים                  |
|  הדגמה (60 דק'): מפתחים מדגימים       |
|    תוכנה חיה — לפי ערך עסקי          |
|  משוב (20 דק'): לקוח מגיב,           |
|    SM מתעד כל פריט                     |
|  סיכום (5 דק'): עדכוני Backlog,       |
|    תצוגה מקדימה לספרינט הבא           |
+----------------------------------------+
| כללי הדגמה:                            |
|  ✅ תוכנה חיה בלבד (לא שקפים!)       |
|  ✅ רק פריטים שעברו DoD               |
|  ✅ כל מפתח מדגים את העבודה שלו       |
|  ✅ הליכה דרך תסריטי משתמש            |
+----------------------------------------+
| משוב → פעולה:                          |
|  באג → Bug Work Item ב-Azure DevOps   |
|  רעיון חדש → Story חדש ב-Backlog      |
|  שינוי → עדכון Story קיים             |
+========================================+
```

### כרטיס 5: Sprint Retrospective

```
+========================================+
|       SPRINT RETROSPECTIVE             |
+========================================+
| TIMEBOX: עד שעה וחצי                  |
| מי: צוות פיתוח + SM + PO (רצוי)       |
| בלי מנהלים! בלי לקוחות! מרחב בטוח.   |
+----------------------------------------+
| שלב 0: סקירת Action Items קודמים      |
|   מה בוצע? מה לא? למה?               |
+----------------------------------------+
| פורמטים (מחליפים כל ספרינט!):         |
|  1. Start / Stop / Continue            |
|  2. מפרשית (רוח/עוגן/סלעים)          |
|  3. 4L (אהבתי/למדתי/חסר/רציתי)       |
|  4. Mad / Sad / Glad                   |
+----------------------------------------+
| הזרימה:                               |
|  1. פתיחה (5 דק') — Prime Directive   |
|  2. איסוף נתונים (15-20 דק') — כתיבה  |
|  3. קיבוץ ודיון (20-30 דק')          |
|  4. הצבעה — 3 נקודות לאדם (5 דק')    |
|  5. Action Items (15-20 דק')          |
|  6. סגירה (5 דק')                     |
+----------------------------------------+
| כללי Action Items:                     |
|  1. ספציפי (לא "לשפר X")             |
|  2. אחראי אחד                         |
|  3. דדליין = הספרינט הבא              |
|  4. מקסימום 2-3 לספרינט               |
|  → הופכים ל-Tasks בספרינט הבא         |
+========================================+
```

### כרטיס מצב 2: Scope Creep באמצע הספרינט

```
+========================================+
|  מצב: מישהו רוצה להוסיף עבודה         |
|        באמצע הספרינט                   |
+========================================+
| אבחון: גבול ספרינט חלש, PO לא אומר   |
|         "לא", "הכל דחוף"              |
+----------------------------------------+
| מה לעשות:                              |
|  1. SM: "זה תומך ב-Sprint Goal שלנו?" |
|  2. אם לא → "מוסיפים ל-Backlog        |
|     לספרינט הבא"                       |
|  3. אם באמת דחוף → PO מנהל מו"מ:     |
|     "כדי להכניס X, מה מוציאים?"        |
|  4. תעדו כל הוספה → דונו ב-Retro      |
|  5. יעד: 0 הוספות אחרי Planning       |
+========================================+
```

## כרטיס בונוס: User Story

```
+========================================+
|         כרטיס USER STORY               |
+========================================+
| תבנית:                                 |
|  בתור [תפקיד],                         |
|  אני רוצה [פעולה],                     |
|  כדי [ערך].                            |
+----------------------------------------+
| בדיקת INVEST:                          |
|  [I] Independent — ללא תלויות         |
|  [N] Negotiable — פתוח לדיון          |
|  [V] Valuable — מספק ערך למשתמש       |
|  [E] Estimable — הצוות יכול להעריך    |
|  [S] Small — נכנס בספרינט אחד (≤8)   |
|  [T] Testable — ניתן לאמת עם בדיקות  |
+----------------------------------------+
| פורמט Acceptance Criteria:             |
|  בהינתן [תנאי מקדים],                 |
|  כאשר [פעולה],                         |
|  אז [תוצאה צפויה].                    |
+----------------------------------------+
| דוגמה:                                 |
|  בתור משתמש רשום,                      |
|  אני רוצה לאפס סיסמה במייל,           |
|  כדי שאוכל לחזור לגשת למערכת.          |
|                                        |
|  AC1: בהינתן שאני בדף ההתחברות,        |
|       כאשר לוחץ "שכחתי סיסמה",         |
|       אז מקבל מייל תוך 2 דקות.         |
|  Story Points: 5                       |
+========================================+
```

## כרטיס בונוס: Definition of Done

```
+========================================+
|      כרטיס DEFINITION OF DONE         |
+========================================+
| DoD — משימה (Task):                    |
|  [ ] קוד כתוב ורץ                     |
|  [ ] בדיקות יחידה כתובות ועוברות      |
|  [ ] Code Review ע"י לפחות מפתח אחד   |
|  [ ] תיעוד עודכן (אם צריך)           |
+----------------------------------------+
| DoD — סיפור (Story):                   |
|  [ ] כל ה-Tasks עומדים ב-Task DoD     |
|  [ ] כל ה-AC אומתו                    |
|  [ ] בדיקות אינטגרציה עוברות          |
|  [ ] נפרס ל-Staging בהצלחה            |
|  [ ] PO בדק וקיבל                      |
+----------------------------------------+
| DoD — ספרינט (Sprint):                 |
|  [ ] כל ה-Stories עומדים ב-Story DoD  |
|  [ ] Sprint Review בוצע (הדגמה)       |
|  [ ] Retro בוצע + Action Items        |
|  [ ] אין פריטים תקועים ב-Active       |
+----------------------------------------+
```
