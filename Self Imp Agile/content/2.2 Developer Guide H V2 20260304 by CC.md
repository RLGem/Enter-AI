# מדריך למפתח/ת — Agile מנקודת המבט שלך

> **גרסה:** 2.0 | **תאריך:** 04.03.2026
> **קהל יעד:** מפתחים ו-QA — כולם חלק מצוות הפיתוח
> **זמן קריאה:** 8 דקות
> **תוצר:** את/ה יודע/ת בדיוק מה מצופה ממך, ויש לך כלים ביד

---

## TL;DR — אם יש לך רק דקה

1. **את/ה עדיין כותב/ת קוד כל היום.** הטקסים (Ceremonies) לוקחים 9% מהזמן. כל השאר — פיתוח.
2. **את/ה מעריך/ה את העבודה שלך.** אף אחד לא מכתיב לך כמה זמן לוקח.
3. **את/ה בוחר/ת משימות.** ב-Planning הצוות מחליט — לא המנהל.
4. **את/ה מדגים/ה מה בנית.** ב-Review — תוכנה חיה, לא שקפים.
5. **QA הוא חלק ממך.** Definition of Done אומר שאת/ה גם בודק/ת.

---

## מה משתנה — ומה נשאר

| מה חדש (ושקל) | מה נשאר בדיוק כמו קודם |
|:-------------|------------------------:|
| Daily Standup — 15 דקות כל בוקר, עומדים | את/ה כותב/ת קוד |
| Planning — פעם ב-3 שבועות, 3 שעות | את/ה פותר/ת בעיות טכניות |
| את/ה מעריך/ה כמה זמן דברים לוקחים | את/ה עושה Code Review |
| את/ה מזיז/ה כרטיסים בלוח (Board) | את/ה לומד/ת טכנולוגיות חדשות |
| את/ה מדגים/ה ב-Review | את/ה מתקן/ת באגים |

> **שורה תחתונה:** השינוי הכי גדול הוא שעכשיו **יש לך קול.** את/ה מחליט/ה כמה עבודה הצוות לוקח, את/ה בוחר/ת מה לעבוד עליו, ואת/ה אומר/ת כשמשהו לא ריאלי.

## היום שלך ב-Agile

### יום רגיל (שבוע 1-2)

</div>

```
09:00  Daily Standup (15 דקות, עומדים)
       → מה עשיתי אתמול
       → מה אעשה היום
       → מה חוסם אותי

09:15  עדכון לוח — הזזת כרטיסים
       (15 דקות)

09:30  קוד. קוד. קוד.
       Code Review. בדיקות. PR.

       ...כל היום...

       → כשסיימת משימה: הזז ל-Done (רק אם עבר DoD!)
       → כשנתקעת: דבר עם הצוות, או שאל את AIlex
```

<div dir="rtl">

### ימים מיוחדים

| מה קורה | מתי |
|:---------|----:|
| **Planning** — 3 שעות. PO מציג מה צריך. את/ה שואל/ת שאלות, מעריך/ה גודל, בוחר/ת משימות. | ראשון, שבוע 1 |
| **Refinement** — 1.5 שעות. PO מציג פריטים לספרינט הבא. את/ה שואל/ת שאלות טכניות, מזהה סיכונים. | רביעי, שבוע 2 |
| **Review** — 1.5 שעות. את/ה מדגים/ה תוכנה עובדת. לא שקפים — **Live Demo!** | חמישי, שבוע 3 |
| **Retro** — 1 שעה. מה עבד, מה לא, מה נשפר. היה כנ/ה — זה מרחב בטוח. | חמישי, שבוע 3 |

> **לוח הזמנים המלא** נמצא ב**לוח הספרינט** שלך (Sprint Playbook Chart) — הדפס אותו ותלה מעל המסך.

## הלוח (Board) — הכלי היומי שלך

הלוח ב-Azure DevOps הוא המפה שלך. תמיד שקוף, תמיד מעודכן.

</div>

```
┌──────────┬──────────────┬───────────────┬──────────────┬──────────┐
│   New    │   Active     │  In Review    │   Testing    │   Done   │
│  (חדש)   │  (בעבודה)    │ (בסקירת קוד) │  (בבדיקות)   │  (הושלם) │
├──────────┼──────────────┼───────────────┼──────────────┼──────────┤
│ Story A  │ ← אתה כאן   │               │              │ Story F  │
│ Story C  │              │               │              │ Story G  │
└──────────┴──────────────┴───────────────┴──────────────┴──────────┘

כלל: כרטיס זז ימינה רק כשהוא באמת עבר שלב.
     "Done" = עבר Definition of Done. לא "סיימתי לכתוב קוד".
```

<div dir="rtl">

### Definition of Done — מתי "סיימתי" באמת?

"סיימתי" לא אומר "כתבתי קוד." סיימתי אומר:

- [ ] הקוד כתוב ועובד
- [ ] יש בדיקות (Unit Tests / Integration)
- [ ] עבר Code Review
- [ ] תועד (אם צריך)
- [ ] נפרס לסביבת בדיקות
- [ ] עבר QA

> **QA הוא חלק ממך.** בצוות Agile, אין "מעביר ל-QA." את/ה אחראי/ת שמה שעשית עובד. QA מסייע — אבל האחריות שלך.

## הערכות — את/ה מחליט/ה

ב-Planning וב-Refinement, הצוות מעריך כמה "גדולה" כל משימה. אנחנו משתמשים ב-**Story Points** — מספרים יחסיים שמשווים משימות אחת לשנייה.

| דוגמה | גודל | Story Points |
|:------|:-----|------------:|
| שינוי צבע כפתור | קטן מאוד | 1 |
| הוספת שדה לטופס עם ולידציה | קטן | 2 |
| API חדש עם בדיקות | בינוני | 5 |
| אינטגרציה עם מערכת חיצונית | גדול | 8 |
| שכתוב מודול שלם | גדול מאוד | 13 |

> **אל תפחד/י להעריך "לא נכון."** אין הערכה נכונה — יש הערכה שמשתפרת עם הזמן. אחרי 2-3 ספרינטים, תהיו הרבה יותר מדויקים.

## כשנתקעים

| מה לעשות | המצב |
|:---------|-----:|
| דבר/י עם חבר צוות — זה לא חולשה, זה שיתוף פעולה | **בעיה טכנית** |
| תעלה את זה ב-Daily. ה-SM ירים את זה. | **חסימה (Blocker)** |
| אמור/י ב-Daily — "אני לא בטוח שנסיים את X". הצוות יעזור לסדר עדיפויות. | **לא מספיקים את הספרינט** |
| לגיטימי. תעלה ב-Retro. | **הטקסים מרגישים מיותרים** |
| שאל/י את AIlex: "אני מפתח/ת, שבוע 2, ויש לי [תאר את הבעיה]" | **לא בטוח/ה מה לעשות** |

## 5 דברים שכדאי לזכור

1. **עדכן/י את הלוח כל יום.** לפני ה-Daily — הזז/י כרטיסים. לוח לא מעודכן = אף אחד לא יודע מה קורה.

2. **אל תקח/י יותר מדי.** ב-Planning, עדיף להתחייב על פחות ולסיים — מאשר להתחייב על הרבה ולא לעמוד.

3. **Done = Done.** אל תזיז/י כרטיס ל-Done אם לא עבר DoD. "כמעט סיימתי" זה עדיין In Progress.

4. **דבר/י.** ב-Daily, ב-Retro, בכל יום. אם משהו חוסם אותך, אם משהו לא ברור, אם יש לך רעיון — תגיד/י.

5. **טעויות זה בסדר.** ספרינט נכשל? לא הערכנו נכון? תיקנו ב-Retro. זה לא כישלון — זה למידה.
